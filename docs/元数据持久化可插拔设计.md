## 1. 背景与目标

### 1.1 背景

对象存储侧（local / cos / oss / s3）已按 Provider + 依赖裁剪接入；文件**元数据**（现 `sys_files`）仍绑死 MyBatis：

- `FileMetadataRepository` 在 `qof-spi` 中已声明，但**未接入运行时**
- 落库实际走 `QofExtService` → `FilesService` → `SysFiles`
- `FilesService extends IService<SysFiles>`，接口泄漏 ORM
- Web 直连 `FilesService`，无法换 Mongo / ES / Redis

### 1.2 目标

1. **元数据与对象存储解耦**：fileId 语义由元数据仓储提供  
2. **依赖即选型**：引入哪个 `starter-persistence-*`，就启用哪个后端；**禁止**再用 `qof.metadata.type` 配置切换  
3. **元数据强制落库**：不允许「只要对象存储、不落元数据」；无仓储实现则**启动失败**  
4. **本期只交付 MySQL**：其余后端后续官方开发；业务可**自行实现 SPI** 扩展  
5. **能力诚实**：分页检索等为可选能力接口，不强求 Redis 等后端等价实现  
6. **Public API 一次收敛**：删除 `FilesService` / `SysFiles` 等对外落库表面，只留 SPI + Client  

### 1.3 硬约束

| 约束 | 说明 |
|---|---|
| 依赖决定实现 | 引入 `…-persistence-mysql` → MySQL；引入 `…-persistence-mongo` → Mongo。**无** `qof.metadata.type` |
| 单一官方写实现 | 同时引入两个及以上官方 persistence starter → **启动报错** |
| 必须有仓储 | 无 `FileMetadataRepository` Bean（未引 starter 且未自实现）→ **启动报错** |
| 禁止 Noop 业务模式 | 不提供面向业务的「不落库」合法路径 |
| fileId 一等公民 | 上传必写元数据；下载/删除必能按 fileId 解析路径与存储模式 |
| 允许覆盖官方 Bean | 官方用 `@ConditionalOnMissingBean`；业务先声明自己的 Repository 即可覆盖 |
| 无旧版兼容 | 不保留 `starter-persistence` / `persistence-mybatis` 别名；不 Deprecated 过渡 `FilesService` |

### 1.4 交付范围（本期 / 后续）

| 项 | 本期 | 后续 / 业务自建 |
|---|---|---|
| 本期官方元数据 | ✅ 单模块 `qof-spring-boot-starter-persistence-mysql`（实现 + 自动配置） | — |
| SQLite / Mongo / ES / Redis 官方 starter | ❌ 不实现 | 官方排期或业务自实现 SPI；形态建议同 mysql（单模块 starter） |
| 自定义仓储 | ✅ 支持：业务实现 `FileMetadataRepository`（及可选 `FileMetadataQuery`） | — |
| 跨后端数据迁移工具 | ❌ | 运维/业务自行处理 |
| 对象删除失败兜底 | ❌ 仅日志 | 后续独立方案 |

### 1.5 非目标

- 不强制统一宿主鉴权 / `Result` 模型  
- 不把 JDBC / MyBatis 等**访问技术**写进 artifactId（对外只按存储后端命名）  
- 不做方案二式「旧 API Deprecated 保留数个小版本」

## 3. 统一抽象与扩展点（方案三）

### 3.1 命名约定

| 层级 | 规则 | 示例 |
|---|---|---|
| 模块 / starter | 按**存储后端** | `mysql`、`mongo`、`sqlite`、`es`、`redis` |
| 实现技术 | 仅模块内部 | MySQL 内可用 JDBC + MyBatis-Plus，对外不叫 `*-mybatis` / `*-jdbc` |

落地时：`qof-persistence-mybatis` **替换为单模块** `qof-spring-boot-starter-persistence-mysql`（实现 + 自动配置同 jar），**不**再单独建 `qof-persistence-mysql`，**不留**旧坐标别名。

### 3.2 抽象点（核心契约）

这些是**稳定 Public API**：换后端、业务自建实现，都只面向它们。  
类的放置：契约型接口/模型优先在 `qof-spi`；带 Spring/Client 编排的适配实现可在 `qof-core`（见 §3.6）。

#### 抽象点 A — 中立模型 `FileMetadata`

**用途：** 对象存储路径信息与具体库表/文档结构之间的中立载体。Client、Web、各 persistence 实现只传递本对象，禁止直接依赖 `SysFiles`。

| 字段 | 类型 | 用途 |
|---|---|---|
| `fileId` | `Long` | 文件主键；上传前由 Client 生成（雪花），落库与下载/删除查询键 |
| `fileName` | `String` | 原始文件名（含后缀），下载 Content-Disposition 等 |
| `filePath` | `String` | 对象存储侧完整相对路径/key |
| `fileType` | `String` | MIME，如 `image/png` |
| `fileLabel` | `String` | 业务标签（证件照、报告等），可选 |
| `fileSize` | `Long` | 字节大小 |
| `fileStorageMode` | `String` | 存储模式：`local` / `cos` / `oss` / `rustfs`… |
| `fileStorageStation` | `String` | 存储站别名（多 bucket/多目录） |
| `publicAccess` | `Integer` | `1` 公开 / `0` 私有 |
| `createId` | `Long` | 创建者；私有文件鉴权用 |
| `createTime` / `updateTime` | `LocalDateTime` | 审计时间；由仓储写入或回填 |
| `attributes` | `Map<String,Object>` | 扩展字段；官方核心链路可不读；业务/自建仓储可按需持久化 |

**形态：** 普通 class + getter/setter（不用 record）。无业务行为方法。  
**关系：** `QofFileInfoDto` / `QofFileInfoBo` ↔ `FileMetadata` 互转；表实体仅 mysql 模块内部映射，**不对外导出**。  
**fileId：** 允许业务预传；未传则 Client 雪花生成后再落库。  
**fileStorageStation：** 为空时回落配置中的 default station 再写库/再定位对象。
#### 抽象点 B — 必选仓储 `FileMetadataRepository`

**用途：** 元数据唯一读写端口。换 MySQL/Mongo/自建实现，只换本接口的 Bean。

| 方法 | 作用 | 典型调用方 |
|---|---|---|
| `type()` | 返回实现标识（如 `"mysql"`、`"custom:acme"`），仅日志/诊断/互斥报错；**不用于**配置选型 | 启动校验、日志 |
| `findById(fileId)` | 按 id 查元数据；empty=不存在 | 下载、删除、鉴权、预览 |
| `save(metadata)` | **新增**元数据，返回 `fileId`（通常与入参一致） | 上传成功后落库 |
| `update(metadata)` | 按 `fileId` 更新已有记录（改标签、公开性等） | 后续管理 API |
| `deleteById(fileId)` | 逻辑删或物理删；true=元数据侧成功 | 删除流程 |

```java
public interface FileMetadataRepository {
    String type();
    Optional<FileMetadata> findById(Long fileId);
    Long save(FileMetadata metadata);
    void update(FileMetadata metadata);
    boolean deleteById(Long fileId);
}
```

#### 抽象点 C — 可选查询 `FileMetadataQuery`（说明见下）

**它是做什么的？**

- **不是**下载/删除所需能力；下载删除只靠 `FileMetadataRepository.findById` / `deleteById`。  
- **专门**给「文件管理列表」用：按条件分页查元数据（文件名模糊、存储模式、存储站等）。  
- 对应现状：`qof-web` 的 `GET .../page` → 现 `FilesService.pageFiles(...)`。方案三后应改为注入 `FileMetadataQuery`。  
- 为何与 Repository 拆开：Redis 等后端往往能按 id 读写，但难做等价分页检索；拆开后「能管文件」与「能列表检索」可独立演进。

| 方法 | 作用 |
|---|---|
| `page(criteria)` | 按条件分页返回 `FileMetadata` |

无 Query Bean 时：上传 / 下载 / 删除仍可用；**列表 API** 返回 501 或明确业务异常。
```java
public interface FileMetadataQuery {
    PageResult<FileMetadata> page(FileMetadataQueryCriteria criteria);
}
```

#### 抽象点 D — 生命周期落库：`MetadataPersistenceListener`

**是什么：** `FileLifecycleListener` 的官方实现，**只负责落元数据**，不做鉴权/审计。

| 方法 | 行为 |
|---|---|
| `afterUpload(ctx)` | 上下文 → `FileMetadata` → `repository.save(...)` |
| `beforeDelete(ctx)` | **先** `repository.deleteById`；失败则返回 `false` / 抛错，**中止后续删对象** |
| `afterDelete` | 一般空；对象侧失败已由 Client 记日志 |
| 其余钩子 | 默认空 |

```java
public class MetadataPersistenceListener implements FileLifecycleListener {
    private final FileMetadataRepository repository;
}
```

业务审计 Listener 与本类**并存**（`@Order` 协调）。  
方案三下：**不再**保留 `MetadataBackedQofExtService` / Ext 落库职责；Client 直接调 Listener 链 + Repository（查询场景）。

##### 删除流程（已拍板）

```text
delete(fileId)
  1. findById → 得到路径 / storageMode
  2. beforeDelete 链：MetadataPersistenceListener 删元数据
       └─ 失败 → 整次删除失败（回滚/中止），不碰对象存储
  3. 对象存储 delete
       └─ 失败 → 打日志，接口可按约定返回「元数据已删、对象残留」或仅日志；暂不补偿
```

影响：可能短暂出现「库无记录、对象仍在」；接受，后续兜底。

#### 抽象点 E — 装配与互斥

| 规则 | 行为 |
|---|---|
| 0 个官方 persistence 且无用户 Repository Bean | 启动失败 |
| ≥2 个官方 persistence starter | 启动失败 |
| 恰好 1 个官方实现 | 自动注册 Repository（及 Query），且 `@ConditionalOnMissingBean` |
| 用户自建 Repository（可同时不引官方 starter，或覆盖官方 Bean） | 合法 |

不使用 `qof.metadata.type`。

### 3.3 扩展点（谁可以插什么）

```text
EP-1  FileMetadataRepository     换/自建元数据写存储
EP-2  FileMetadataQuery          换/自建列表与检索（可选）
EP-3  FileLifecycleListener      上传下载删除前后横切（含官方落库 Listener）
EP-4  ObjectStorageProvider      换对象存储（既有）
EP-5  官方 persistence-* 模块    后续 sqlite/mongo/…
```

| 扩展点 | 谁实现 | 怎么接入 | 约束 |
|---|---|---|---|
| EP-1 | 官方 / 业务自建 | starter 或 `@Bean` | 全局一个写实现；官方 Bean 可被 MissingBean 覆盖 |
| EP-2 | 同上 | 同上 | 无 Bean 则列表按约定降级 |
| EP-3 | 业务 + 官方落库 Listener | Spring 列表 + Order | 落库勿注册两套 |
| EP-5 | 组件维护者 | 新模块 + starter | 遵守互斥与命名 |

### 3.4 运行时协作

```text
业务 / Web
    ├─ QofClientFactory → QofClient
    └─ FileMetadataRepository [+ Query]

AbstractQofClient
    └─ List<FileLifecycleListener>
              └─ MetadataPersistenceListener → FileMetadataRepository
```

切换元数据后端 = 改 Maven 依赖（或换自建 Bean），不改 YAML type。

### 3.6 `qof-spi` 与 `qof-core`：**已确认保持拆分**

| 模块 | 内容 | 依赖 |
|---|---|---|
| `qof-spi` | Provider / Listener / `FileMetadata` / Repository / Query | **零重依赖** |
| `qof-core` | Client、工厂、校验、DTO/BO、官方 `MetadataPersistenceListener` 装配 | Spring 等 + spi |

mysql 实现模块只依赖 spi（+ 自身 ORM），不把表实体泄漏进 core。

### 3.7 Listener「强类型上下文」是什么？（题意说明，待你拍板是否本期做）

**现状问题：** `FileLifecycleListener` 方法参数是 `Object context`（见现有 SPI）。实现方必须自己 `instanceof` / 强转，容易转错、IDE 无提示、文档与真实字段脱节。

**「强类型上下文」指：** 把 `Object` 收成明确类型，例如：

```java
void afterUpload(UploadContext ctx);
boolean beforeDelete(DeleteContext ctx);
```

`UploadContext` / `DownloadContext` / `DeleteContext` 内携带本次操作已知字段（fileId、路径、存储模式、操作者等），Listener 直接 getter，无需猜测。

| 它解决什么 | 不解决什么 |
|---|---|
| 扩展方写 Listener 时的类型安全与可读性 | 不替代 Repository；也不单独决定「删库还是删对象」 |
| 官方 `MetadataPersistenceListener` 从 ctx 取字段落库更稳 | 不解决多 Listener 顺序（仍靠 `@Order`） |

**与 `MetadataPersistenceListener` 的关系：** Listener 是钩子机制；强类型上下文是钩子的**入参形状**。  
**本期决定：** 一并落地强类型上下文，替换现有 `Object context`。

## 5. 方案三：落地设计（唯一路径）

### 5.1 定位

一次到位建立 **SPI 抽象 + 依赖选型 + 互斥启动校验 + MySQL 官方实现**，并 **删除** 旧落库 Public API。

适合：直接走破坏性升级（建议版本号 **18.0.0**）；接入方按升级指南改依赖与代码。

### 5.2 目标模块结构

```text
qof-spi                              # FileMetadata + Repository + Query + Listener 契约
qof-core                             # Client；MetadataPersistenceListener；缺 Repository / 多实现 → Fail Fast

qof-spring-boot-starter-persistence-mysql  # 本期唯一官方元数据（实现 + AutoConfiguration；实体不对外）

# 后续官方（本期不建；形态同 mysql：单模块 starter）
# qof-spring-boot-starter-persistence-mongo | sqlite | es | redis

# 删除（不做兼容别名）
# qof-spring-boot-starter-persistence
# qof-persistence-mybatis
# qof-web（源码并入 starter-web）
# qof-spring-boot-autoconfigure（空壳已移除）
# （不建）qof-persistence-mysql
```

### 5.3 实现步骤

1. **SPI 强类型化**  
   - `FileMetadata`；`FileMetadataRepository` / `FileMetadataQuery` 签名不含 `Object`、不含 MyBatis 类型  

2. **core 绑定抽象**  
   - Client 走 `FileLifecycleListener` 链；官方注册 `MetadataPersistenceListener`  
   - 删除 Noop 落库路径；删除 `QofExtService` 落库职责（类本身按清理清单删除或移出 Public API）  
   - `persistent-enable=false` 非法（启动失败）  

3. **互斥与必选校验（抽象点 E）**  
   - `0` 且无用户 Bean → 失败；官方 starter `≥2` → 失败  
   - 官方 Bean：`@ConditionalOnMissingBean`  

4. **MySQL 实现（落在 `qof-spring-boot-starter-persistence-mysql`）**  
   - `MysqlFileMetadataRepository` / `MysqlFileMetadataQuery` + AutoConfiguration  
   - 表实体仅模块内部；**删除**对外 `FilesService` / `SysFiles` / `AbstractQofServiceImpl`  

5. **Web（单模块 `qof-spring-boot-starter-web`，含原 qof-web）**  
   - **不**传递 persistence 依赖；宿主自行引 `starter-persistence-mysql` 或自建 Repository  
   - 上传下载删除：`QofClient` + `FileMetadataRepository`  
   - 分页：`FileMetadataQuery`；无 Bean 时列表接口返回 501/明确异常  

6. **文档与 examples**  
   - 只演示：`starter` + `starter-persistence-mysql`  
   - 自定义：业务 `@Bean FileMetadataRepository`

### 5.5 清理清单（相对现状）

| 项 | 做法 |
|---|---|
| `FilesService` / `SysFiles` / `SysFilesMetaBo` 对外导出 | **删除**（实现可留 starter-persistence-mysql internal） |
| `QofExtService` 落库职责 / `AbstractQofServiceImpl` | **删除**对外扩展路径 |
| `NoopQofExtService` | **删除** |

## 10. 调整后的系统模块树

> 方案三定稿：`qof-web`、元数据 MySQL 均采用「实现并入对应 starter」；不建独立 `qof-persistence-mysql`。

```text
qof-parent
├── qof-spi                              # 契约：FileMetadata / Repository / Query /
│                                        #   FileLifecycleListener + Upload|Download|DeleteContext /
│                                        #   ObjectStorageProvider
├── qof-core                             # Client / 工厂 / DTO·BO /
│                                        #   MetadataPersistenceListener 装配与互斥校验
│
├── qof-storage-local                    # 对象存储：本地磁盘
├── qof-storage-cos                      # 对象存储：腾讯云 COS
├── qof-storage-oss                      # 对象存储：阿里云 OSS
├── qof-storage-s3                       # 对象存储：S3 兼容
│
├── qof-spring-boot-starter              # 主 starter（core + local）
├── qof-spring-boot-starter-cos          # 可选：COS
├── qof-spring-boot-starter-oss          # 可选：OSS
├── qof-spring-boot-starter-s3           # 可选：S3
├── qof-spring-boot-starter-persistence-mysql  # MySQL 元数据（实现 + AutoConfiguration）
│                                        #   Repository / Query；表实体 internal
├── qof-spring-boot-starter-web          # 内置 HTTP（原 qof-web 源码迁入）
│                                        #   Controller / Properties / 自动配置
│                                        #   ★ 不传递 persistence-*
│
└── qof-examples                         # 示例：仅保留 mysql 元数据演示

# ---------- 相对现状的增减 ----------
# 删除：
#   qof-web                              → 源码并入 starter-web
#   qof-persistence-mybatis               → 能力并入 starter-persistence-mysql
#   qof-spring-boot-starter-persistence  → 由 starter-persistence-mysql 取代
#   qof-spring-boot-autoconfigure        → 空壳移除；配置元数据迁入 core / starter-web
#
# 不建：
#   qof-persistence-mysql
#
# 新增：
#   qof-spring-boot-starter-persistence-mysql
#
# 后续官方扩展位（本期不建；单模块 starter）：
#   qof-spring-boot-starter-persistence-mongo | sqlite | es | redis
```
